# 行きたい場所（登録・一覧・編集・削除）

機能ごとの仕様書。前書き（実装範囲と確認のルール。docs/specs/ の仕様書全体に適用される）、やらないこと（[4章](overview.md#4-やらないこと重要)）、用語（[5章](overview.md#5-用語)）など全体の前提は [overview.md](overview.md) を参照。

## 7-1. 登録

入力項目は3つだけ。

1. 場所の名前（手入力）
2. 一言（必須）
3. 距離感（近場 / 日帰り / 遠出 から選ぶ。初期値なし）

外部 API は呼ばない。オートコンプリートは存在しない。

同じ場所の重複登録を機械的に防ぐ手段はない（一意な識別子を持たないため）。入力中に既存の place を部分一致で表示するヒントは、初期リリースでは見送る。

登録に成功したら完了メッセージを出し、空のフォームに戻る（続けて登録できるようにするため）。

## 7-2. 一覧

行きたい場所（消化済みでない場所）の一覧で、画面名は「行きたい場所」。自分のグループの場所を**登録が新しい順**に並べる。

- 各行に表示するのは、場所の名前 / 一言 / 距離感。時間・距離の数値表記は出さない（[6節](overview.md#6-データモデル)）
- 上部の「すべて / 近場 / 日帰り / 遠出」のボタンで距離感ごとに絞り込む。デフォルトは「すべて」。選択中のボタンは塗りつぶしで示す
- 絞り込みは URL のクエリ（例: `/places?q[distance_eq]=near`）で行う。並び順は URL から変えられず、常に新しい順
- 各行に「訪問を記録」リンクを置き、訪問の記録画面（[7-4](visits.md#7-4-訪問記録)）を開く。見た目は「編集」リンクと同じ

**0件のとき**

場所が0件になる理由（登録なし・すべて消化・絞り込んだ結果だけ0件・距離感に不正な値が指定された）によらず、一律で「場所がありません」と表示し、登録画面への導線を置く。不正な値（例: `q[distance_eq]=xxx`）でもエラーにはしない。

- 行きたい場所が1件もない（すべて消化済みも含む）：絞り込みボタンと見出し横の登録ボタンは出さず、案内文と登録リンクだけにする
- 行きたい場所はあるが絞り込んだ結果だけ0件：ほかの距離感に切り替えられるよう、絞り込みボタンは表示したままにする

## 7-5. 編集・削除

登録した場所を直したり、片付けたりする。

**編集**

- 一覧（[7-2](#7-2-一覧)）の各行の「編集」リンクから編集画面を開く。編集画面には行きたい場所に戻るリンクを置く
- 入力項目とバリデーションは登録（[7-1](#7-1-登録)）と同じ3つ（場所の名前 / 一言 / 距離感）。フォームは登録画面と共通
- 開いた時点で今の値が入っている
- 更新に成功したら「○○を更新しました」と表示して行きたい場所に戻る（絞り込みは解除される）
- 入力エラーのときは、入力値を残したまま編集画面を再表示する

**削除**

- 編集画面の下に「削除する」ボタンを置く。一覧から直接は消せない
- 押すと確認ダイアログを出し、OK で DB から完全に消す（論理削除・ゴミ箱・取り消しはない）
- 削除したら「○○を削除しました」と表示して行きたい場所に戻る

**削除と消化（[7-4](visits.md#7-4-訪問記録)）の違い**

- 削除：**行かずにやめた場所**を消す。閉店した、興味がなくなった、二重に登録した、など。記録は何も残らない
- 消化：**行った場所（また行きたくない）**を行きたい場所から外す。訪問記録（visits）として残る。「また行きたい：はい」で記録した場所は行きたい場所に残る

**権限**

自分のグループの場所だけを編集・削除できる。他のグループの場所の id を直接指定しても、表示・更新・削除はできない（見つからない扱いにする）。
